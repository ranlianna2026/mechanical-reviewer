# Mechanical Reviewer

**From a drawing to a verified fix.** Upload a 2D mechanical drawing. The agent
reads it with Muse Spark, finds design-for-manufacturing problems, highlights
them (SAM 3.1), explains how each one fails in the field with real NHTSA recall
evidence, then fixes the design and proves the fix: the corrected drawing is
re-rendered, re-checked and re-read.

Built for the Meta Global AI Developer Hackathon (Oct 26 – Nov 4, 2026), Indie
track, *Push the Frontier* (manufacturing). Everything in this repo was built
during the event.

## How it works

```
drawing.png
  → extract       Muse Spark (vision, JSON schema) → structured part spec + evidence boxes
  → check         deterministic DFM rules (mechreview/rules.py)
  → verify        Muse Spark re-reads a zoomed crop of each issue's evidence; drops misreads
  → highlight     SAM 3.1 geometry boxes + Muse Spark evidence boxes
  → explain       failure chain + analogous NHTSA recalls (local index of 1,067 mechanical recalls)
  → fix loop      Muse Spark proposes edits → apply (whitelisted fields) → validate geometry
                  → re-check; failures are fed back to the next attempt (≤ 3 rounds)
  → re-verify     render the fixed drawing and extract it again; must come back clean
```

The rules are deliberately simple and deterministic: they are the verifier.
The model's job is the hard part, reading the drawing, judging evidence,
explaining failure and proposing design changes, and every model output is
checked by code before it is trusted.

## Benchmark

`eval/` holds 25 synthetic drawings with 30 planted issues (5 each of thin
wall, sharp internal corner, deep small hole, deep narrow slot, overly tight
tolerance, missing general tolerance) and 77 hard negatives, plus an answer key
with pixel regions. See [eval/README.md](eval/README.md).

```bash
.venv/bin/python eval/score.py            # live, needs MODEL_API_KEY
.venv/bin/python eval/score.py --oracle   # offline pipeline sanity check
```

Reports extraction field accuracy, per-type recall, precision, highlight IoU,
fix pass rate and re-verify clean rate.

## Run it

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # add MODEL_API_KEY from dev.meta.ai
.venv/bin/python -m uvicorn app.server:app --port 8000
open http://127.0.0.1:8000
```

Without a key the app runs in a clearly labeled offline mode on the sample
drawings (ground-truth extraction, reference fixer), so the flow can be shown
without API calls.

Other entry points:

| Command | What |
|---|---|
| `.venv/bin/python eval/generate_eval_set.py` | regenerate the benchmark (deterministic) |
| `.venv/bin/python scripts/fix_demo.py D05` | before/after fix with the reference fixer |
| `.venv/bin/python -m unittest discover tests` | offline tests |
| `.venv/bin/python scripts/build_recall_index.py FLAT_RCL_POST_2010.txt` | rebuild the NHTSA index |

## Layout

| Path | |
|---|---|
| `mechreview/rules.py` | DFM rules + checker |
| `mechreview/drawing.py` | part spec → drawing, with pixel regions per feature |
| `mechreview/fix.py` | fix loop: apply, normalize, validate, re-check, feedback |
| `mechreview/extract.py` | Muse Spark drawing extraction |
| `mechreview/agents.py` | verify, explain (with recalls), propose |
| `mechreview/meta_api.py` | Meta Model API client (Muse Spark, SAM 3.1) |
| `mechreview/pipeline.py` | end-to-end review |
| `app/` | demo web app |
| `data/recalls.jsonl` | filtered NHTSA recalls (public domain) |

## Limitations

- One part family (machined plates with a pocket, holes, a slot) and clean
  generated drawings. Real scanned drawings are harder.
- Rule thresholds are common shop guidelines, not a formal standard.
- Recall matches are analogies for the failure mechanism, not claims that a
  given recall was caused by the same design flaw.
- This is a design-review aid; an engineer signs off on changes.
